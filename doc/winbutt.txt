EXPM - Window button module (XpmWinButtonClass)
===============================================

The window button module provides the window class XpmWinButtonClass, a
push-button control that is a drop-in replacement for the system button
(WC_BUTTON) with extra presentation features: flat buttons, bitmap
faces, thin frames, automatic sizing and mouse enter/leave
notifications.  It is a clean-room reimplementation for the EXPM project
(2026) of the AsuaCtl 1.0 window button (WC_WINBUTTON).  It was written
in C from the published AsuaCtl header (include/winbutt.h) and the
published IPF help text only; no AsuaCtl source was consulted, so the
behaviour below is EXPM's own interpretation of that published API.
AsuaCtl is GPLv2, EXPM is LGPLv3.

Every public name carries the EXPM "Xpm" prefix:

    WC_WINBUTTON        ->  XpmWinButtonClass ("XpmWinButton")
    BtnRegister         ->  XpmWinButtonInit
    BS_*                ->  XpmBS_*
    BM_QUERYHEIGHT/WIDTH->  XpmBM_QUERYHEIGHT/WIDTH
    BN_*                ->  XpmBN_*
    WBTNCDATA / PWBTNCDATA -> XpmWBTNCDATA / PXpmWBTNCDATA
    BBMP_*              ->  XpmBBMP_*


Creating the control
--------------------

    #define INCL_WIN
    #include <os2.h>
    #include "expm.h"

    XpmControlsInit( hab );                       /* register classes */

    WinCreateWindow( hwndParent, XpmWinButtonClass, "OK",
                     WS_VISIBLE | XpmBS_DEFAULT,
                     x, y, cx, cy,
                     hwndParent, HWND_TOP, id, pCtlData, NULL );

XpmControlsInit must have been called first (it calls
XpmWinButtonInit).  XpmWinButtonInit may be called on its own when only
the window button is used.  The creation text holds the button label;
for a bitmap face it may instead use the AsuaCtl form
"#<id1>#<id2>\ttext" (see "Bitmaps" below).  pCtlData points to an
XpmWBTNCDATA structure (see "Bitmaps").

The button is a standard WS_ window; give it WS_VISIBLE, an identity and
call WinEnableWindow( hwnd, FALSE ) to disable it.


Styles
------

    XpmBS_FLATBUTTON    0x0001  flat: no frame until the pointer is over
                                it (then a frame and full colour)
    XpmBS_OWNERDRAW     0x0008  the owner paints the background
    XpmBS_ALIGNLEFT     0x0000  text placement (see below)
    XpmBS_ALIGNRIGHT    0x0010
    XpmBS_ALIGNTOP      0x0020
    XpmBS_ALIGNBOTTOM   0x0030
    XpmBS_ALIGNMASK     0x0030
    XpmBS_THINFRAME     0x0080  one-pixel frame (default is two pixels)
    XpmBS_AUTOTEXT      0x0400  draw "..." when the text does not fit
    XpmBS_BITMAP        0x0040  a bitmap is used for the face
    XpmBS_HELP          0x0100  notify with WM_HELP instead of WM_COMMAND
    XpmBS_SYSCOMMAND    0x0200  notify with WM_SYSCOMMAND
    XpmBS_DEFAULT       0x1000  thick default-button frame
    XpmBS_AUTOSIZE      0x4000  resize to fit the text and/or bitmap

The alignment field (XpmBS_ALIGNMASK) selects where the text sits:
XpmBS_ALIGNLEFT (left, vertically centred), XpmBS_ALIGNRIGHT (right,
vertically centred), XpmBS_ALIGNTOP (top, horizontally centred) or
XpmBS_ALIGNBOTTOM (bottom, horizontally centred).

AsuaCtl reused the WC_BUTTON style bit-space with its own meaning, so
these values intentionally overlap PM's BS_* bits; they are only
meaningful to XpmWinButtonClass.  AsuaCtl gave XpmBS_DEFAULT the value
0x0400, which collides with XpmBS_AUTOTEXT; EXPM renumbers it to 0x1000.


Messages
--------

    XpmBM_QUERYHEIGHT    (WM_USER+25)  Returns the minimum height needed
                                       to show the current face.
    XpmBM_QUERYWIDTH     (WM_USER+26)  Returns the minimum width.

The PM messages BM_CLICK (simulate a click) and BM_AUTOSIZE (resize to
the minimum size) are also handled.


Notifications
-------------

The owner receives messages in the usual way:

    XpmBN_CLICKED          1  left button released inside (WM_COMMAND)
    XpmBN_DBLCLICKED       2  double click            (WM_COMMAND)
    XpmBN_PAINT            3  (reserved)
    XpmBN_MOUSEENTER       4  pointer entered        (WM_CONTROL)
    XpmBN_MOUSELEAVE       5  pointer left           (WM_CONTROL)
    XpmBN_MOUSECHANGE      6  (reserved, not generated)
    XpmBN_PRESPARAMCHANGED 7  a PP_* changed         (WM_CONTROL)
    XpmBN_BUTTON2CLICKED   8  right button released inside (WM_COMMAND)

Clicks are also generated by the space bar and Enter when the button has
the keyboard focus.  When XpmBS_SYSCOMMAND is set a click is sent as
WM_SYSCOMMAND; when XpmBS_HELP is set it is sent as WM_HELP.  Otherwise
it is a WM_COMMAND with ussource = CMDSRC_OTHER and uspointer = TRUE for
a mouse click, FALSE for a keyboard click.


Colours
-------

The button reads its colours from presentation parameters, falling back
to the system colours and finally to hard-coded defaults:

    background  PP_BACKGROUNDCOLOR         SYSCLR_BUTTONMIDDLE
    text        PP_FOREGROUNDCOLOR         SYSCLR_WINDOWTEXT
    disabled bg PP_DISABLEDBACKGROUNDCOLOR SYSCLR_BUTTONMIDDLE
    disabled fg PP_DISABLEDFOREGROUNDCOLOR SYSCLR_BUTTONDARK
    light edge  PP_BORDERLIGHTCOLOR        SYSCLR_BUTTONLIGHT
    dark edge   PP_BORDERDARKCOLOR         SYSCLR_BUTTONDARK
    default     PP_BORDERDEFAULTCOLOR      SYSCLR_BUTTONDEFAULT

An RGB colour (for drag-and-drop from a palette) is a GPI value in the
form 0x00RRGGBB.


Owner-drawn background (XpmBS_OWNERDRAW)
----------------------------------------

With XpmBS_OWNERDRAW the button asks its owner to paint the background
before drawing the frame, bitmap and text.  The owner receives
WM_DRAWITEM with:

    mp1 = MPFROM2SHORT( id, 0 )
    mp2 = PXpmOwnerBack

XpmOwnerBack (see expm.h) carries the window handle, the presentation
space and the rectangle (client coordinates) to repaint.  Return TRUE if
the background was painted; return FALSE and the button fills it with
its own background colour.  The presentation space is in colour index
mode; call GpiCreateLogColorTable( hps, LCOL_RESET, LCOLF_RGB, 0, 0,
NULL ) before drawing with RGB values.


Bitmaps
-------

A bitmap face may be supplied two ways:

  * through XpmWBTNCDATA (pCtlData at creation).  hColorImage /
    hColorDisImage / hColorPressImage / hColorHiliteImage are the colour
    bitmaps for the normal / disabled / pressed / mouse-over states, and
    hImage / hImageDis / hImagePress / hImageHilite are the matching
    monochrome transparency masks.  Any handle may be NULL.  With
    XpmBS_FLATBUTTON supply the mouse-over bitmap so the face turns to
    full colour on hover.  fsHiliteState requests an initially pressed
    look.

  * through the creation text "#<id1>#<id2>\ttext", where id1/id2 are
    resource ids of the normal and disabled bitmaps.  EXPM parses and
    strips this prefix (the remaining text is the label) but does NOT
    load the resources: the AsuaCtl resources are not shipped and the
    toolkit headers EXPM builds against do not declare WinLoadBitmap.
    Pass the handles through XpmWBTNCDATA instead.  XpmBBMP_OK / _CANCEL
    / _HELP are defined for source compatibility only.

Bitmaps are drawn with XpmDrawBitmap, centred in the client rectangle.


Interpretation notes
--------------------

AsuaCtl's header documents styles, the CTLDATA layout and the new
notifications but ships no bitmap images and leaves several details
implicit.  EXPM implements a faithful, self-contained subset:

  * mouse-leave (XpmBN_MOUSELEAVE) is detected when PM delivers a
    WM_MOUSEMOVE whose coordinates are outside the client area, or when
    the pointer leaves while the button has captured the mouse (during a
    press).  The system does not always deliver the boundary move, so a
    leave notification may be missed if the pointer jumps straight to
    another window.
  * XpmBN_MOUSECHANGE is reserved and not generated.
  * disabled faces are not greyed at run time; supply a disabled bitmap
    (hColorDisImage) instead.


Building and sample
-------------------

    compile_wat.cmd

Outputs: dll\expm.dll, lib\expm.lib, sample\winbutt\wbsmp.exe.

sample\winbutt\wbsmp.exe shows normal, default, thin-frame, disabled and
flat buttons, the four text placements, the XpmBS_AUTOTEXT ellipsis, an
XpmBS_AUTOSIZE button and an owner-drawn button, and reports clicks and
mouse enter/leave events in a status field.  It expects expm.dll on
LIBPATH (or next to the EXE).
